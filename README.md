# nit

Нативный Android-клиент к `nit-gui`. Один экран: морфящий док снизу (инпут,
поиск и список чатов), транскрипт, композер. Своего бэкенда нет: приложение говорит с существующим
Go-прокси `nit-gui`, который уже держит сессии OpenCode, загрузки, SSE и гейт.

Пакет: `space.bongdo.nit`. `minSdk 26`, `targetSdk 35`. Kotlin 2.0, Compose
Material 3.

## Что уже есть

- Вход по имени и паролю через существующую страницу `/login` гейта. Кука
  сессии хранится в `EncryptedSharedPreferences` (Android Keystore). Код 2FA
  вводится там же, если он включён.
- Список чатов: «Ждут и готовы» и «Работают» отдельными категориями, перелив
  waiting/done/failed как в web, поиск в верхней строке дока, фильтр по папке,
  черновики, новый чат. Список живёт в том же доке, что и инпут.
- Транскрипт: markdown, таблицы, код с копированием, HTML-превью в песочнице
  без сети, превью фото-вложений, карточки shell-команд, ошибки шага и
  сводки сжатия контекста.
- Стриминг через `/api/events` (SSE): статусы connecting/online/offline,
  переподключение с джиттером, догон сообщений и форм после обрыва, health-цикл
  каждые 20 с, офлайн-баннер с повтором, остановка и догрузка старых сообщений.
- Чат создаётся первым промптом, без пустых сессий; агент и модель берутся из
  `/api/ui`. Перегрузка провайдера повторяет тот же промпт до пяти раз. Если
  промпт не ушёл, созданная сессия удаляется, а не остаётся пустой.
- Холодный кэш: `filesDir/chats.json` хранит сессии и до 24 транскриптов по 60
  сообщений. Кэшируется только видимое — текст, вопросы, ошибки, compaction;
  reasoning и tool-детали вырезаются. 12 свежих чатов предзагружаются в фоне.
- Шаги агента: компактная строка «шаги · N» с текущим действием, таймером и
  счётчиком; раскрытие догружает полное сообщение через `messages/{id}` и не
  попадает в кэш.
- Композер: текст, файлы (изображения/PDF/что угодно) с превью, отправка,
  стоп, очередь/steer. Стрелка отправляет, Enter переносит строку.
- Прозрачная шапка: лента едет под ней. Свайп вниз по шапке открывает меню
  чата (папка, тема, настройки, форк, откат, субагенты). Язычок или верхняя
  кромка инпута поднимает док: инпут превращается в поиск, ниже раскрывается
  список чатов. Тап по язычку открывает и закрывает, свайп вниз по списку до
  самого верха подхватывает док и закрывает его.
- Фокус и клавиатура появляются только когда лента упирается в дно после
  ручной прокрутки, и снимаются сразу при уходе со дна.
- Карточки разрешений и форм, чтобы ход не вставал на вопросе агента.
- Смена модели и агента, тема (system/dark/light), размер текста.
- Сборка debug APK: `bin/apk`.

Чего нет в этой версии: роли ассистента и оверлея, удалённых push-уведомлений,
полного офлайн-режима с очередью, TTS/STT, дерева субагентов в общем списке
(есть меню субагентов), экрана инстансов, share intent, кропа картинок,
фонов-сцен, review/curator и web-спеллчекера. Часть из этого — браузерная
механика, часть сознательно оставлена на следующую волну.

## Сборка

```sh
bin/check     # unit tests + lint + assembleDebug
bin/apk       # copy the APK to dist/nit-debug.apk and print the path
```

`bin/check` сам находит JDK 17 в nix store. Android SDK ожидается в
`~/Android/Sdk` (или `ANDROID_HOME`).

На aarch64 официальный `aapt2` из build-tools собран под x86_64. Поэтому
`tools/aapt2` запускает его через `qemu-x86_64` с x86_64 glibc из nix store;
Gradle получает этот файл через `-Pandroid.aapt2FromMavenOverride`. На x86_64
обёртка просто передаёт вызов настоящему бинарнику.

## Сервер

В приложении адрес вводится целиком, например `https://bongdo.space/nit`.
Логин уходит на `origin/login` того же хоста, API — на `origin/nit/api/*`.
Пароль проверяет сервер; приложение не хранит пароль, только cookie.

Если сервер за reverse proxy с другим префиксом, достаточно поменять адрес:
логин всегда берётся от корня хоста, API — от пути.

## Архитектура

```
MainActivity
  AppViewModel        состояние, SSE, действия
    NitApi            OkHttp + cookie jar, JSON
    EventStream       /api/events, переподключение
    StreamReducer     события OpenCode → Message
    SettingsStore     DataStore
    SecureStore       EncryptedSharedPreferences
  ui/                 Compose-экраны
```

Один модуль `:app`. Для MVP этого достаточно; разделение на `core:*` и
`feature:*` имеет смысл, когда появятся независимые волны (виджет, офлайн, TTS).

## Проверки

- `app/src/test` — reducer стрима, контракт API, SSE и backoff, склейка
  снапшота, retry, running-состояния, activity/шаги, кэш и его лимиты,
  markdown, токенизатор синтаксиса, темы, разбор HTML-артефактов и file links,
  типы файлов.
- Ручной сценарий: выключить сеть → баннер и повтор; новый чат → сессия
  появляется только после промпта; стоп до ответа → пустой чат исчезает;
  перегрузка → повтор того же сообщения; вход → список чатов → ответ с таблицей
  и HTML → вложение → разрешение → смена модели → выход.
- Проверка окон: ссылка на файл, HTML-fence, `[[html:path]]`, вложение и PDF
  должны открыться отдельной карточкой в Recents, а не поверх чата.
