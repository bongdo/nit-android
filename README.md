# nit-android

Android-клиент для nit-gui. Сейчас здесь только план: кода нет, решение не принято.

Источник правды по чату и бэкенду — `../nit-gui`. Публичный адрес:
`https://frankfurt.tailf358cb.ts.net/nit/`.

## Что уже готово в nit-gui

| Слой | Состояние |
| --- | --- |
| UI | React 19 + Tailwind, ~11 700 строк компонентов, тёмная/светлая темы |
| Мобильная вёрстка | drawer, свайп от края, `viewport-fit=cover`, 27 файлов с DOM API |
| PWA | `manifest.json`, иконки 192/512/maskable, `display: standalone`; service worker нет |
| Бэкенд | Go-прокси, cookie `nit_gate` (7 дней), SSE `/api/events`, загрузки, TTS/STT |
| Доступ | публичный HTTPS через Tailscale Funnel, один пароль на все gui |

Диктовка в вебе: Web Speech API, а при его отсутствии — запись через `getUserMedia`
и `POST /api/stt` на сервер. То есть запасной путь для WebView уже есть.

## Варианты

| Вариант | Работа | Переиспользование | Ассистент Android |
| --- | --- | --- | --- |
| PWA: service worker + `share_target` + `shortcuts` | 0.5–1 день | 100% | нет |
| TWA (Bubblewrap) поверх Funnel-URL | +1–2 дня, нужен `assetlinks.json` и подпись | 100% | нет |
| Capacitor-оболочка (как в `../nita/web/android`) | 3–5 дней | 100% чата | да, long-press power |
| React Native | 3–6 недель до паритета | ~20–30% логики, UI переписать | да, но всё равно Kotlin-модуль |
| Нативный Kotlin/Compose | 6+ недель | 0% UI | да, лучший |

React Native не отменяет нативный слой: роль ассистента — это
`VoiceInteractionService` + `RecognitionService` + `VoiceInteractionSession`,
в RN такого нет. Зато RN теряет готовый чат: markdown, таблицы, подсветку кода,
sandbox-превью HTML (нужен `react-native-webview`), темы, свайпы.

## Рекомендация

1. **PWA-полировка в nit-gui.** Service worker, `share_target` (текст/ссылка из
   любого приложения), `shortcuts` («Новый чат», «Последний чат»). Ставится из
   Chrome, обновляется само, ничего не публикуется.
2. **Capacitor-оболочка, только если нужны нативные фичи.** WebView грузит тот же
   Funnel-URL: куки, SSE и относительные `/api` работают без правок фронтенда.
   Нативные куски: роль ассистента, share intent с файлами, микрофон, TTS,
   уведомления, плитка быстрых настроек.
3. **React Native — не сейчас.** Если после реального использования мобильный UX
   упрётся в WebView (жесты, офлайн, виджеты), тогда отдельный проект и честные
   3–6 недель.

Рабочий референс роли ассистента уже есть в `../nita/web/android` (Java, ~60 строк):
сервис, сессия, recognition-заглушка, `intent-filter ACTION_ASSIST`.

## Что реально даёт «ассистент»

- Long-press кнопки питания на Android 12+ открывает приложение с микрофоном.
- Голос — системный `RecognizerIntent` или серверный STT; «Ok Google» и hotword
  без привилегий недоступны.
- Чтение экрана (`AssistStructure`) — отдельный нативный парсер, в v1 не нужен.
- Пользователь сам выбирает приложение в «Цифровом ассистенте»; Play-политика
  такие оболочки проверяет строже, чем APK на сайдлоаде.

## Ограничения, которые надо помнить

- **Уведомления в фоне.** SSE живёт только пока приложение открыто. Для
  «агент просит разрешение, пока телефон в кармане» нужен FCM (Firebase, Google
  Play) или `ntfy`/UnifiedPush на сервере. Это отдельная работа на бэкенде.
- **WebView.** `webkitSpeechRecognition` в Android WebView нет — пойдёт медленный
  серверный путь. `getUserMedia` требует runtime-разрешения и обработки
  `onPermissionRequest` в оболочке.
- **Офлайн.** При загрузке Funnel-URL без сети — пустой экран. Офлайн-очередь
  сообщений — только у RN/нативного клиента.
- **Пароль.** Оболочка хранит cookie, а не пароль. Ротация `bin/auth` разлогинит
  все устройства.
- **Публичный хост.** Мобильный клиент не должен расширять то, что уже открыто:
  тот же `/nit/`, тот же пароль, тот же лимит попыток.
