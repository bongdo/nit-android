# Решения

## 2026-11-17 — Нативный Compose-клиент вместо оболочки

Контекст: nit-gui уже ставится PWA и открывается в Bare; для мобильного нужны
нативные жесты, выделение, IME и нормальные листы. Роль ассистента и оверлей
отложены: это отдельная, хрупкая по прошивкам работа.

Решение: Kotlin + Jetpack Compose, один `Activity`, один модуль `:app`. Клиент
ходит в существующий Go-прокси nit-gui, не в OpenCode напрямую.

Почему: чат — это список сообщений, композер и SSE; WebView-оболочка не даёт
нативного выделения, predictive back и IME. Бэкенд уже есть, дублировать его
не нужно.

Что отвергли: Capacitor/PWA на этом этапе (быстро, но остаётся WebView),
React Native (нет готового чата и нативных ручек), роль ассистента и оверлей
(цена — недели, ценность — один ярлык).

Цена: второй рендерер markdown и второй reducer стрима. Держим их маленькими и
сверяем с `../nit-gui/web/src/lib/stream.ts`.

## 2026-11-17 — Вход через существующий `/login` гейта

Контекст: гейт уже выдаёт HttpOnly-куки `gate_session` и `nit_gate` после
POST-формы `/login`. Отдельного JSON-логина нет.

Решение: приложение отправляет ту же форму (`name`, `password`, `code`, `next`)
и сохраняет полученные куки в `EncryptedSharedPreferences`. Пароль не хранится.

Почему: не расширяем поверхность атаки новым эндпоинтом и не заводим второй
механизм токенов; отзыв сессии остаётся в гейте.

Что отвергли: JSON-логин в nit-gui, WebView для страницы входа, долгоживущий
токен в APK.

Цена: приложение зависит от формы логина и её полей; при смене полей гейта
нужно обновить `NitApi.login`.

## 2026-11-17 — Один модуль, без Room и офлайна

Контекст: MVP должен открываться, показывать сессии, стримить ответ, принимать
файлы и вопросы агента. Офлайн-очередь и кэш — отдельная волна.

Решение: один модуль, DataStore для настроек, без Room и без локальной копии
транскрипта. Открытый чат каждый раз читается с сервера.

Почему: меньше кода и нет второго источника правды; сервер и так хранит сессии.

Что отвергли: Room, офлайн-очередь, кэш последних 200 сообщений, фоновые пуши.

Цена: без сети видна только ошибка; при переключении чата — загрузка.

## 2026-11-17 — aapt2 через qemu на aarch64

Контекст: официальный `aapt2` в Android build-tools существует только под
x86_64, а рабочая машина — aarch64.

Решение: `tools/aapt2` запускает бинарник через `qemu-x86_64` с x86_64 glibc и
libgcc из nix store; Gradle получает путь через
`-Pandroid.aapt2FromMavenOverride` (это делает `bin/check`).

Почему: позволяет собирать APK локально без x86_64-машины и без ручной сборки
aapt2 из AOSP.

Что отвергли: сборку только на удалённом x86_64, termux-aapt2 (собран под
Bionic и не запускается на glibc), GitHub Actions как единственный путь.

Цена: сборка медленнее, зависит от наличия qemu и x86_64 glibc в nix store.

## 2026-11-17 — Транскрипт без процесса агента

Контекст: мобильный экран тонул в reasoning и списках инструментов; это web-режим
для разработчика, а не сообщение пользователю.

Решение: приложение не рендерит reasoning и tool-части вообще. Остаются текст
пользователя, текст агента, live-форма вопроса и исторический блок «вопрос →
ответ». Ошибки шага показываются отдельной карточкой.

Почему: на телефоне важен ответ, а не ход; лишние строки ломают чтение и скролл.

Что отвергли: сворачиваемые steps (как в web) и ленивую догрузку tool-деталей.

Цена: диагностировать зависший ход по экрану нельзя, только по ошибке/логам.

## 2026-11-17 — Черновики: DataStore + `/api/ui/drafts`

Контекст: web хранит черновик в localStorage и синхронизирует его серверным
`/api/ui/drafts`, включая tombstone для пустого текста.

Решение: Android хранит текст в DataStore по ключу сессии или `new:<dir>`,
обновляет сервер после паузы 350 мс и при восстановлении читает сервер, если
локально пусто. Пустая отправка/очистка отправляет tombstone. В списке чатов
есть карандаш.

Почему: текст не теряется при переключении чатов, смерти процесса и между
телефоном и web.

Что отвергли: файлы черновика (нужен отдельный store и очистка TTL), хранение
только на сервере (лаг при каждом вводе).

Цена: ключи должны совпадать с web, иначе синхронизация не сработает; вложения
черновика пока не восстанавливаются.

## 2026-11-17 — Все темы web как локальные палитры

Контекст: в web 13 именованных тем + system; CSS-переменные включают не только
Material-цвета, но и spark/success/attention и синтаксис.

Решение: `Themes.kt` содержит палитры всех тем, `MaterialTheme` собирается из
них, `LocalSyntaxPalette` задаёт цвета кода, `ThemeSheet` показывает сетку
превью. HTML-превью получает только dark/background, как web.

Почему: тема — это идентичность продукта и читаемость, а не один accent.

Что отвергли: 3 темы и производные цвета; CSS-переменные в WebView.

Цена: палитры нужно обновлять вручную при изменении `index.css`.

## 2026-11-17 — HTML и файлы отдельными задачами

Контекст: пользователь просил открывать страницы и файлы как новые окна Bare.

Решение: `PreviewActivity` (`launchMode=standard`, `exported=false`) запускается
с `FLAG_ACTIVITY_NEW_DOCUMENT | FLAG_ACTIVITY_MULTIPLE_TASK`, ставит
`TaskDescription` и рендерит HTML/markdown/текст/изображение/PDF/медиа. Основное
приложение сначала скачивает содержимое через `/api/artifact`, `/api/view` или
`/api/file` в cache, поэтому WebView не нужны cookie и Binder не тащит HTML.

Почему: каждая карточка в Recents живёт отдельно, как вкладка Bare; большой HTML
не упирается в лимит транзакции.

Что отвергли: диалог поверх чата (неудобно на телефоне), WebView с cookie
главного приложения, PDF только через внешнее приложение.

Цена: cache-файлы не чистятся сразу; офлайн-просмотр после перезапуска может
не работать, если файл удалён.


## 2026-11-17 — Очередь/steer и локальные уведомления

Контекст: мобильный композер умел только стоп-и-отправь, терял вложения
черновика и не сообщал о вопросе в фоне.

Решение: при работающем ходе показываем выбор «в текущий ход» (steer, по
умолчанию) и «в очередь» (queue); `delivery` уходит в `/prompt`. Вложения
черновика храним в DataStore как `UserFile`-описания (уже загруженные пути).
Уведомления — локальные из SSE через ProcessLifecycle, без FCM; тап открывает
сессию.

Почему: это закрывает реальные сценарии телефона без серверной инфраструктуры
пушей и без второго клиента.

Что отвергли: FCM/ntfy (нужен внешний сервис), авто-фокус на каждом открытии
чата.

Цена: уведомления не приходят после смерти процесса.

## 2026-11-17 — Грамматику и spellcheck убрали из приложения

Контекст: кнопка проверки грамматики и лист замен оказались лишними для
мобильного сценария; пользователь попросил убрать spellcheck.

Решение: `/api/grammar`, кнопка, лист и модель ответа удалены из клиента.

Почему: проверка отвлекает от отправки и дублирует клавиатуру.

Цена: серверная грамматика остаётся доступна web-версии.


## 2026-11-18 — Дно ленты, шапка и детали транскрипта

Контекст: автопрокрутка ставила верх последнего сообщения к верху экрана, из-за
чего клавиатура открывалась не вовремя, а стрелка «вниз» не доходила до конца.
Шапка просвечивала полосой статус-бара, фото-вложения выглядели как файлы,
сжатие контекста не отображалось.

Решение: «дно» считается через `!canScrollForward`, прокрутка идёт в конец
списка с `Int.MAX_VALUE`; прокрутка следует за контентом, пока пользователь сам
не отлип. Полоса статус-бара закрашена фоном, ниже шапка плавно растворяется.
Фото грузятся в Coil с cookie и показываются превью в композере и сообщении.
Compaction-сообщения и busy-строка рендерятся как в web. Субагенты и настройки
переехали в свайп-меню шапки, «...» из шапки убран.

Почему: это возвращает предсказуемый скролл и совпадает с макетом web.

Что отвергли: ручной расчёт высоты контента, отдельную шторку субагентов,
кнопку «...» в шапке.

Цена: фото-превью требуют сеть и cookie; при истёкшей сессии картинка не
загрузится, но файл откроется через превью.
