# Решения

## 2026-11-17 — Нативный Compose-клиент вместо оболочки

Контекст: nit-gui уже ставится PWA и открывается в Bare; для мобильного нужны
нативные жесты, выделение, IME и нормальные листы. Роль ассистента и оверлей
отложены: это отдельная, хрупкая по прошивкам работа.

Решение: Kotlin + Jetpack Compose, один `Activity`, один модуль `:app`. Клиент
ходит в существующий Go-прокси nit-gui, не в OpenCode напрямую.

Почему: чат — это список сообщений, композер и SSE; WebView-оболочка не даёт
нативного выделения, predictive back и IME. Бэкенд уже есть, дублировать его
не нужно.

Что отвергли: Capacitor/PWA на этом этапе (быстро, но остаётся WebView),
React Native (нет готового чата и нативных ручек), роль ассистента и оверлей
(цена — недели, ценность — один ярлык).

Цена: второй рендерер markdown и второй reducer стрима. Держим их маленькими и
сверяем с `../nit-gui/web/src/lib/stream.ts`.

## 2026-11-17 — Вход через существующий `/login` гейта

Контекст: гейт уже выдаёт HttpOnly-куки `gate_session` и `nit_gate` после
POST-формы `/login`. Отдельного JSON-логина нет.

Решение: приложение отправляет ту же форму (`name`, `password`, `code`, `next`)
и сохраняет полученные куки в `EncryptedSharedPreferences`. Пароль не хранится.

Почему: не расширяем поверхность атаки новым эндпоинтом и не заводим второй
механизм токенов; отзыв сессии остаётся в гейте.

Что отвергли: JSON-логин в nit-gui, WebView для страницы входа, долгоживущий
токен в APK.

Цена: приложение зависит от формы логина и её полей; при смене полей гейта
нужно обновить `NitApi.login`.

## 2026-11-17 — Один модуль, без Room и офлайна

Контекст: MVP должен открываться, показывать сессии, стримить ответ, принимать
файлы и вопросы агента. Офлайн-очередь и кэш — отдельная волна.

Решение: один модуль, DataStore для настроек, без Room и без локальной копии
транскрипта. Открытый чат каждый раз читается с сервера.

Почему: меньше кода и нет второго источника правды; сервер и так хранит сессии.

Что отвергли: Room, офлайн-очередь, кэш последних 200 сообщений, фоновые пуши.

Цена: без сети видна только ошибка; при переключении чата — загрузка.

## 2026-11-17 — aapt2 через qemu на aarch64

Контекст: официальный `aapt2` в Android build-tools существует только под
x86_64, а рабочая машина — aarch64.

Решение: `tools/aapt2` запускает бинарник через `qemu-x86_64` с x86_64 glibc и
libgcc из nix store; Gradle получает путь через
`-Pandroid.aapt2FromMavenOverride` (это делает `bin/check`).

Почему: позволяет собирать APK локально без x86_64-машины и без ручной сборки
aapt2 из AOSP.

Что отвергли: сборку только на удалённом x86_64, termux-aapt2 (собран под
Bionic и не запускается на glibc), GitHub Actions как единственный путь.

Цена: сборка медленнее, зависит от наличия qemu и x86_64 glibc в nix store.
